# Decisions

Autonomous run (no human to ask). Ambiguities resolved with the simplest safe option; reasons below.

| # | Topic | Decision | Why |
|---|-------|----------|-----|
| 1 | Go module location | `go.mod` at repo root, module `strikezone`; server in `/server`, client embed package in `/client` | `go:embed` cannot reach outside its package dir. Root module lets `client/embed.go` embed `/client` while `cd server && go run .` still works. |
| 2 | Go version | `go 1.24` (toolchain installed in the sandbox: 1.24.7) | "Latest stable" = what is installable offline-ish here. Nothing 1.25-specific is used. |
| 3 | three.js | r170 `three.module.min.js` copied to `client/vendor/` (+ MIT license) | No CDN: must work on LAN without internet. Only the core module is needed (no loaders/controls). |
| 4 | Shared spec | `client/shared/spec.json` (hitboxes, movement, weapons, match rules) and `client/shared/map.json` are the single source for client **and** server. Server reads them through the same `go:embed` FS. | Spec said hitbox dims must live in one place; same for map collision. |
| 5 | Empty remote | `tuanden0/strike-zone` was empty (no `main`). Work lives on `feature/fps-mvp`. | A PR needs an existing base branch; creating `main` would violate the "never push main" rule, so the PR was not opened and REPORT.md gives the one-line fix. |
| 6 | `.env` | Server reads only real env vars. `.env.example` is reference; `scripts/run.*` source `.env` if present. | No dotenv dependency (YAGNI). |
| 7 | CSP | Strict CSP header (`'self'` only, `ws:`/`wss:` for connect). No inline script/style. | Cheap defence-in-depth; client has no inline code. |
| 8 | Practice mode | Offline range (dummies) kept as a permanent lobby button, not just a milestone-1 stub. | Cheap, useful for smoke tests, no server needed. |
| 9 | Netcode | Client sends one input per 30 Hz tick (`seq`, axes, yaw/pitch, buttons) — never positions. Server simulates with the same fixed step; snapshot carries `ack` + authoritative state; client replays unacked inputs (prediction + reconciliation); remote players are interpolated 100 ms behind. | Speed/teleport hacks impossible by construction; JS and Go movement are locked together by a golden test. |
| 10 | Input flooding | Server processes ≤1 input/tick sustained (token budget, burst 3, ≤2/tick), queue capped at 8. | Without this, sending 60 inputs/s would give 2x speed. |
| 11 | Movement model | Full air control, instant velocity (no accel), AABB vs boxes, no step-up, no player-vs-player collision. | Deterministic and tiny to port exactly to Go; good enough for MVP. |
| 12 | Origin policy | Same-origin = Origin host:port equals request Host (scheme ignored); absent Origin allowed (non-browser); extras via `ALLOWED_ORIGINS`. The websocket library's own check is disabled (`InsecureSkipVerify`) because ours replaces it. | Spec; works for localhost and any LAN IP with zero config. |
| 13 | Room passwords | Stored as salted SHA-256, compared with `subtle.ConstantTimeCompare`; never logged or echoed; 5 wrong tries disconnects. | LAN game, not an auth system; avoids plaintext in memory dumps/logs. |
| 14 | Team cap | Each team holds at most ceil(max/2) players; `auto` joins the smaller team. | Keeps teams balanced without extra rules. |
| 15 | govulncheck | Cannot reach vuln.go.dev from the sandbox (egress policy 403). `scripts/check.sh` reports it as SKIPPED loudly instead of passing silently. | Do not route around the egress policy; see SECURITY.md. |
| 16 | Hit detection | Hitscan from the eye, nearest of {map geometry, floor, enemy head/body AABBs}. All players' movement for a tick is applied first, then shots resolve (id order cannot decide a duel; mutual kills possible). Spread uses a server RNG; friendly fire off; spawn-protected and dead players are skipped; firing ends own spawn protection. | Server-authoritative, simple, deterministic in tests (seeded RNG, spread zeroed in tests). |
| 17 | No lag compensation | Server tests the shot against current positions (remote players are rendered ~100 ms in the past). | LAN latency is a few ms; rewind buffers add complexity. Add if Wi-Fi play feels off. |
| 18 | Knife | Same ray code, range 2.2 m, 40 dmg, head multiplier 1. | Reuses hit code; keeps knife from one-shotting on head. |
| 19 | Team switch while dead | Changes team but does not respawn early. | Prevents instant-respawn exploit. |
| 20 | Ammo prediction | Client mirrors the weapon state machine (`weapons.js` == `weapons.go`); snapshot carries ammo/cooldown/reload and client replays unacked inputs through it. | Avoids ammo-counter flicker without trusting the client. |
| 21 | Process | Every commit was preceded by `scripts/check.sh` (gofmt, vet, `go test -race`, gitleaks tree+history). One gitleaks false positive (dummy token in a test) was fixed by constructing the value at runtime instead of allow-listing. | Spec: fix findings before committing. |
| 22 | e2e browser flags | Chromium is launched with `--no-proxy-server`. | The sandbox's egress proxy otherwise intercepts WebSocket traffic to non-localhost IPs; real LAN browsers do not have this. |
| 23 | Instructions files | Task said to read `CLAUDE.md`, `.claude/rules/`, `.claude/skills/`, `docs/reference/`, `client/assets/third_party/`: none of them exist in the repo. Followed the task text and the user's standing preferences only. | Nothing to conflict with. |
| 24 | Blender | No `blender` binary and no apt access; Blender 5.2.2 LTS is installed from the PyPI `bpy` wheel (a package registry, allowed) into a venv outside the repo. Scripts use `import bpy`, so `blender -b -P tools/assets/x.py` and `python tools/assets/x.py` both work. | Task allows package registries only; the wheel is the headless Blender. |
| 25 | Textures | Generated with numpy (periodic FFT noise) and written into Blender images, embedded as JPEG q85 in the glb; maps are 256–512 px (map floor/walls 512). Not "baked" from Blender node trees. | Deterministic, fast, no GPU needed for Cycles bake; same artefact (PBR maps) in the end. |
| 26 | Map assets vs collision | One visual prop per collision box, generated from `client/shared/map.json` so geometry cannot disagree with collision. Only wall lamps (≥3.3 m high) leave the boxes. `map.json` was not changed. | "No gameplay changes". |
| 27 | Hitbox fit | Character authored at exactly 1.80 m; torso/back/shoulders kept ≤1.45 m (e2e asserts it) and the client scales the model by `spec.player.height / model height` (=1.0). Outstretched arms and the held rifle extend beyond the 0.6 m body box in depth (as in any shooter); hits use the unchanged server boxes. | Spec forbids changing the hitbox. |
| 28 | Crouch | `crouch` clip is exported but unused (there is no crouch input; gameplay unchanged). | Spec lists the clip; adding the mechanic would change gameplay. |
| 29 | Animation layering | Leg/body clips (idle, run, crouch) never key arm bones; arm clips (hold_*, shoot_*) never key legs. Client blends run/idle by speed and swaps hold/shoot per weapon. Weapons are bone-parented low-poly meshes inside the character glb. | Layering with plain three.js AnimationMixer, one skinned mesh per character. |
| 30 | Draw calls | Map = one merged mesh (10 draw calls) instead of instancing; a soldier is 19 material primitives. Distant soldiers stop casting shadows (>32 m). "Graphics: Low" option disables shadows. | Fewer calls than instancing for a static map; characters could be atlas-merged later. |
| 31 | CSP | `connect-src` gained `blob:` (GLTFLoader decodes textures through blob URLs). | No external origin added. |
| 32 | PR target | `main` still does not exist in the remote, so the PR into `main` cannot be opened without creating `main` (forbidden). See REPORT.md. | Same situation as the MVP. |
| 33 | e2e under software GL | Tests default to Graphics=Low, small viewports and wait on game state instead of sleeping, because PBR + skinning on SwiftShader runs ~2 fps. | No GPU in the sandbox. |
| 34 | Gameplay extras scope | Pickups, drop/use and map choice change the protocol, which the asset task forbade; this is a separate feature task (branch `feature/gameplay-extras`), so the changes are additive: new optional `in` fields (`drop`,`use`), `you.has`, `pk` message, `create.map`. Old fields unchanged. | Missing fields default to the old behaviour. |
| 35 | Pickups | Server-owned list: map spawn points (respawn 20 s) + dropped weapons (expire 60 s). `use`/`drop` are edge-detected server side; pick-up radius 1.6 m; a held slot is swapped (old weapon drops, ammo kept); knife cannot be dropped; a dead player drops nothing. Reset on match restart. Practice mode has no pickups. | Authority stays on the server; clients only render the `pk` list. |
| 36 | Decals | Bullet holes and blood are client-only cosmetics (not synchronized, not part of simulation): InstancedMesh ring buffers (300 holes, 120 splats, 40 pools), placed from the `shot` event's end point + surface normal found by the same map boxes used for collision. | Zero network cost and no new server state. |
| 37 | Multi-map | `shared/maps.json` registry (id, label, collision file, glb). Server loads all maps at startup (`MapSet`); a room fixes its map at creation. Collision JSON and glb are generated from the same source (`gen_crossroads_map.py`), as for the yard. | Visuals can't disagree with collision. |
| 38 | Crossroads layout | Per user request: empty four-way intersection, no vehicles or street obstacles, one building per corner (enterable, doors/windows). A BFS test checks every spawn/pickup is mutually reachable. | Easy to play; built from original geometry (no copied map data). |
| 39 | Touch controls | `Input` has a touch mode (coarse pointer, or `?touch=1`): `locked` means "touch UI active" because mobile has no Pointer Lock; synthesized mouse events are ignored; stick is digital (-1/0/1) because the protocol takes unit axes. Defaults to Graphics Low. | One input path (`sample()`), identical protocol; no HTTPS needed. |
| 40 | Sniper | Fourth weapon `sniper` appended to `spec.weapons` (indices 0–2 unchanged): damage 100 (one-hit kill on body or head, `maxHealth` is 100), bolt-action (42-tick cycle, not auto), 5+15 rounds, range 400, `pickupOnly` so it is not in the spawn loadout and has to be found on the map. | Power is balanced by pickup-only + slow cycle + hip-fire/moving inaccuracy rather than by lowering damage. |
| 41 | Scope logic | New input bit `scope` (right click toggles it, like most shooters; touch: SCOPE button). Reload, weapon switch, death and pause clear the toggle client-side. Server: `Scoped = scope && weapon.scopeFov > 0 && !reloading`; scoped shots use `scopedSpread` (0) instead of `spread`, `moveSpread` still applies. Client: FOV 78° → `scopeFov` 14° (~5.5x), look sensitivity scaled by tan(fov/2) ratio, overlay + viewmodel hidden. No movement slowdown while scoped (not requested; one number in physics on both sides if wanted). | Accuracy is server-authoritative like everything else; zoom itself is a view-only effect. |
| 42 | Sniper model | `sniper.glb` / `sniper_fp.glb` (Blender, original design: bolt action, scope, thumbhole-ish stock). Not baked into the character glb: the client clones it into the rifle's hand slot at runtime and reuses the rifle hold/shoot clips, because grip/fore-end sit where the rifle's do. | Avoids regenerating and re-validating both character files and their animations. |
| 43 | Recoil | Replaced the per-weapon `recoilPitch/recoilYaw` numbers (which did not follow damage: pistol kicked 3x the rifle) by one rule: view kick = `recoil.perDamage × damage × recoilScale`. Measured change: rifle 0.011 → 0.0135 rad, pistol 0.030 → 0.0113, sniper 0.050 → 0.045. | Higher damage ⇒ stronger kick, enforced by a test over the spec, not by hand-tuned numbers. |
| 44 | Spray accuracy | Consecutive shots (within interval + 6 ticks) build a burst counter (`Player.Burst`, mirrored in `Loadout.burst`, sent as `you.bu/bx` so client replay after reconciliation stays exact). Server adds `bloomRatio(0.25) × kick × bloomScale × (burst-1)` to the spread (cap 12 shots); view kick also ramps +8 %/shot. Sniper and knife have `bloomScale 0`. Spread and kick are checked Go↔JS by golden files. | Accuracy loss is server-side so a client cannot skip it; the view kick stays client-side like before (it only moves the angles the client sends). Numbers are first guesses (30 m rifle: 100 % → 23 % hit rate on a full 12-round spray), untuned by playtest. |
| 45 | Team colours | Soldiers wear the same olive fatigues; team is shown by saturated accents (helmet stripe/tabs, patches, armband, ID strips): **team A red (Ember, #ef4444), team B blue (Cobalt, #3b82f6)**, same colours in the HUD, spawn markings and name labels. Swapped from the earlier A blue / B red at the owner's request. Character body budget raised to 8k tris (6,674 actual) with the olive art pass. | Accents must stay readable against olive; the old teal accent for A was too close to the uniform. |
| 46 | Five more maps | `piazza`, `pyramid`, `canyon`, `harbor`, `bunker` added to `shared/maps.json` (so lobby/practice list them and the server loads them). Original layouts "inspired by classic archetypes"; generic names, no copied geometry, textures, names or logos. Gameplay numbers, server code and protocol untouched: only data, assets and a few client lines (`MODEL_FILES`, practice dummy spots). | Task scope; maps are data. |
| 47 | Grid-authored layouts | Each map is drawn as characters on a 1 m grid (`mapgen_common.py` Canvas: world-metre `fill/put/room`), only the team A half; team B is the same drawing rotated 180 degrees (spawn `A` -> `B`, yaw flipped). A legend maps each character to stacked layers (mat, y0, y1): lintels, sills and bridging arches are just extra layers; adjacent equal cells merge into the fewest boxes. | Both teams get an identical map by construction, doors/walls are easy to get right, and walls are 1 m thick (chunkier than the crossroads' 0.6 m, deliberately). |
| 48 | Reachability checks | Besides the unchanged Go BFS test (`maps_test.go`, 0.4 m grid, jumpable <= 1.0 m obstacles), the generators run a stricter bot-style check: every spawn and pickup must be connected without jumping by routes with 0.8 m clearance on each side (>= 1.6 m wide, sampled every 0.25 m), so no 1-cell diagonal gaps; all passages are >= 2 m (doorways 2-4 m). The generator refuses to write a failing map. | Bots (separate work) will navigate on a 0.5 m grid. |
| 49 | Pyramid tiers | Five tiers of 0.8 m with 2 m treads (top 4.0 m): each tier is one jump (apex ~1.06 m, no step-up). Spawns and pickups are on the floor only (the Go test treats only <= 1.0 m tops as walkable). | Climbable landmark without changing physics. |
| 50 | Map visuals under budget | One prop per collision box from a per-map theme (`mapkit_common.py` + `<id>_kit.py`). Geometry costs ~85 bytes per triangle in a glb (hard edges split normals), so props are cheap: flat quads for facade windows/glass/shutters/markings, no bottom faces on floor-standing boxes, lighter crates and containers than the yard's. Textures 512 px for the big surfaces, 256 for the rest; reused images across tints. Result: 0.70-1.14 MB and 4.5-12.7k triangles per map (limit 1.3 MB / 40k), all models 15.79 MB (limit 20). | Keeps the on-demand download small on LAN/Wi-Fi. |
| 51 | Loading | New glbs are not in `CORE_FILES` (loaded when a room/practice uses the map, as for crossroads); they are in `MODEL_FILES`, which `e2e/assets.mjs` loads (17 models expected). | Startup size unchanged. |
| 52 | Verification | `e2e/maps.mjs` opens Practice on each new map: id, spawn inside bounds on free floor, dummies on free floor, meshes loaded, no console errors, plus two screenshots per map via `game.debugCam` (`docs/screenshots/maps_<id>_overview.jpg`, `_street.jpg`). | Software GL is slow: it waits on game state, not time. |
